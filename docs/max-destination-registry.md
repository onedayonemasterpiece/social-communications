# MAX: реестр часто используемых адресатов

## Назначение

Реестр отделяет пользовательскую формулировку адресата от точного отображаемого названия в MAX. Пользователь может написать «в канал Ух ты», допустить опечатку или использовать устойчивое разговорное название. Семантический планировщик преобразует такую задачу в стабильный `destination.key`, а Playwright-исполнитель перед любым вводом всё равно находит и проверяет точный заголовок открытого чата или канала.

## Источники реестра

Исполнитель объединяет два источника:

1. `config/max-destinations.public.json` — публичные адресаты, названия которых не являются конфиденциальными;
2. repository secret `MAX_DESTINATIONS_JSON` — закрытые чаты, частные aliases и при необходимости переопределения.

Приватная запись с тем же `key` переопределяет `title` и `kind`, а aliases объединяются. В публичные логи выводятся только количества записей; содержимое secret не печатается.

## Зарегистрированные публичные каналы

| Logical key | Точное название в MAX | Тип |
|---|---|---|
| `polubit-kaliningrad-anonsy` | `Полюбить Калининград Анонсы` | `channel` |
| `uh-ty-kaliningrad` | `Ух ты, Калининград!` | `channel` |

Пользовательское название `Ух ты, Калининград` без восклицательного знака также разрешается: punctuation нормализуется, а после открытия проверяется фактический заголовок `Ух ты, Калининград!`.

Пример команды:

```json
{
  "version": 2,
  "requestId": "max-message-20260807-001",
  "destination": {
    "key": "polubit-kaliningrad-anonsy"
  },
  "content": {
    "type": "text",
    "text": "Готовый текст"
  },
  "delivery": {
    "mode": "send_now",
    "timeZone": "Europe/Kaliningrad",
    "recipientInvisiblePreparation": true,
    "reuseExistingStage": true
  }
}
```

## Правила aliases

Alias должен быть достаточно специфичным, чтобы не выбирать адресата по слишком общей фразе. Например, `ух ты` и `анонсы` сами по себе не добавляются: такие формулировки могут совпасть с другими чатами. Разрешены устойчивые варианты с названием бренда или канала, включая безопасные опечатки.

При совпадении alias исполнитель не доверяет строке вслепую. Он ищет точное зарегистрированное `title`, требует ровно один видимый результат и затем проверяет заголовок реально открытого адресата. При нуле или нескольких совпадениях выполнение прекращается до композера.

## Проверка

Workflow `.github/workflows/max-destination-smoke.yml` запускается при изменении публичного реестра или resolver-кода. Он:

- восстанавливает `MAX_SESSION`;
- по очереди разрешает зарегистрированные keys;
- открывает адресата и проверяет заголовок;
- не открывает композер;
- ничего не печатает и не отправляет;
- не создаёт screenshots или Actions artifacts.

Первичная live-проверка: GitHub Actions run `31161071690`, результат `success`, оба адресата разрешены через `registry-key`.

Локально та же проверка запускается так:

```bash
npm install
npx playwright install chromium
npm run max:destination:smoke
```
